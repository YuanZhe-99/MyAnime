# 版本历史

MyAnime!!!!! 的逐版本摘要。在改动一个行为之前理解它*为什么*存在很有用——多条记录记录的是刻意的安全修复，否则看起来像怪癖。

## 仓库注意事项

添加文档指南之前的最近发布标签是 `v0.6.7`，`origin/master` 和 `github/master` 在那里对齐。早期历史有一个褶皱：一次早期的 `git commit --amend` 之后，两个根提交共享相同内容，标签 `v0.1.0` 指向较晚的根。**避免对根提交使用 `git commit --amend`。**

- `v1.3.1`：修复自定义存储路径迁移。更改存储文件夹以前只移动 `anime_data.json`，把 `images/`、`.sync_base/`、`backups/`（捆绑和 blob）和 `webdav_config.json` 遗留在旧位置。最坏的后果是静默的：没有 `.sync_base/`，下一次同步就没有基线快照，于是其他设备已删除的记录被读成"本地新增"并重新上传，在每台设备上复活删除；丢失 `webdav_config.json` 也使同步完全停止，从而禁用了本可修复缺失封面的图像同步。迁移现在移动**整个**存储文件夹，唯独不动 `storage_config.json`（它必须留在原地——它保存路径本身），因此未来版本新增的数据文件无需代码变更即可迁移。既有的目标文件仍然优先，它们的源副本现在留在原地而不是被丢弃。共享逻辑位于 `myapps_data` `v1.0.1` 的 `migrateStorageContents`，由八个测试覆盖。版本统一为 `1.3.1+49` / MSIX `1.3.1.0` / 安装包 `1.3.1`。
