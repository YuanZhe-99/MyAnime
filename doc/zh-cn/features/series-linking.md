# 系列关联

自 1.6.0 起，应用把一部作品的各季、分割播出的各 cour、剧场版和 OVA 归为一个**系列**。详情页以卡片显示系列，上一季/下一季导航遵循系列顺序，用户可以纠正分组。引擎见 [`functions/features/anime/services/series_service.md`](../functions/features/anime/services/series_service.md)，界面见 [`functions/features/anime/views/series_widgets.md`](../functions/features/anime/views/series_widgets.md)，存储的字段是 `seriesLink`（[`../data-formats.md`](../data-formats.md)）。

1.6.0 之前，详情页把 `displayTitle` 完全相同、`season` 标签不同的记录当作"上一季"和"下一季"，并用普通字符串比较排序。`Season 10` 排在 `Season 2` 之前，标题稍有不同的续作永远找不到（`进击的巨人` 对 `进击的巨人 第二季`，或一季用日文标题、下一季用中文标题），而且无法纠正。

## 概念

| 术语 | 含义 |
|---|---|
| **系列** | 属于同一部作品的一组有序记录。 |
| **手动关联的系列** | 共享由用户操作创建的 `seriesLink.seriesId` 的记录。成员完全按用户所设。 |
| **自动归入的系列** | 应用根据标题和资料库关联关系算出的分组。不存储任何内容；在内存中以 `auto:<最小成员 id>` 为键。 |
| **自动记录** | 没有 `seriesLink` 的记录。应用可以把它放进自动归入的系列或手动关联的系列。 |
| **独立（不归入系列）的记录** | `seriesLink.standalone == true`：用户把它移出了所有系列。它从不加入任何系列，也没有记录会加入它。 |

手动关联的系列是固定的。自动分组从不移动手动关联的记录，也从不合并两个手动关联的系列；它只能把**自动**记录挂接到某个系列上。

## `seriesLink` 字段

```json
"seriesLink": { "seriesId": "0b5d0c1e-7f59-4f3e-9d5e-2a1c1b9e8f00", "order": 2 }
```

```json
"seriesLink": { "standalone": true }
```

归属是共享的组 id 而不是前/后指针，因此任何记录都不引用另一条记录的 `id`。删除、合并或导入记录不会留下悬空指针，把 A 关联到 B 也不需要再写一次 B。对象为空时省略，因此 1.5.7 的片库在第一次打开详情页时就会得到自动归入的系列，而不写入任何内容。字段规则与流转表见 [`../data-formats.md`](../data-formats.md)。

## 自动分组

每次详情页加载时，`SeriesIndex.build` 都对整个片库分组。它不写入任何内容。

**标题。** 一条记录的标题是 `title`、`titleJa`、`externalMeta.titleRomaji`、`externalMeta.titleEn` 以及每个别名。它的**基础键**是这些标题去除季标记（`stripSeasonMarkers`：第N季 / 第N期、`Season N`、`2nd Season`、`S2`、`Part N`、`Cour N`、`The Final Season`、最终季 / 完結編、続編、结尾的 II–IV，先把全角字符转为半角）后再归一化（`AnimeSearchService.foldTitle`）的结果。不足 2 个汉字或假名、或不足 4 个拉丁字母或数字的键被丢弃。

**序数。** 记录的季数序数优先从标题读取（任一标题带序数时），否则从 `season` 标签读取，否则为 1——标题优先，因为多数用户从不改动默认的 `Season 1` 标签。没有编号的最终季标记读作 99（`finalSeasonOrdinal`），因此排在每个有编号的季之后。见 [`../functions/shared/utils/season_label.md`](../functions/shared/utils/season_label.md)。

**季标签跟随标题（1.6.1）。** 序数决定顺序，但直到 1.6.0 为止，`season` 标签本身从不更新，因此 `葬送的芙莉莲 第二季` 在卡片和详情页的标签上仍显示 `Season 1`。现在，当记录的标签仍是默认值（`Season 1` 或空，忽略大小写与全半角——`isDefaultSeasonLabel`）时，它会被替换为第一个指明季数的标题给出的 `Season N`（对 `seriesTitlesOf` 运行 `seasonLabelFromTitles`；`derivedSeasonLabel`）：

- 先去除分割放送标记（`Part 2`、`Cour 2`、`第2クール`），因此 `進撃の巨人 The Final Season Part 2` 不会被读作第 2 季。没有编号的最终季、第 1 季标记或根本没有标记时，标签保持不变。
- 只看标题，从不看在系列中的位置，因为 `遊郭編` 这样的篇章名说明不了它是第几季。
- 用户输入的标签——`S2`、`第二季`，除默认值以外的任何内容——绝不被替换。

在哪里运行：
- **已存储的记录**——首页、管理页和详情页通过 `AnimeStorage.loadFixingSeasonLabels(seasonLabelFixups)` 加载，它用 `patchSeasonLabels` 写入修正后的标签。与 `patchExternalMeta` 一样，它**保留 `modifiedAt`**。每台运行 1.6.1 或更高版本的设备都推导出相同的标签，因此不会出现同步冲突；来自另一台设备的较新编辑直接胜出，并在下一次加载时再次被修正。`patchSeasonLabels` 会重新读取文件，并跳过标签已不再是默认值的记录。
- **编辑页**——只要季字段仍显示默认值或它自己推导出的标签，就会跟随标题字段以及已应用的外部元数据中的标题。输入任何其他内容即停止跟随，并且它从不改动「添加下一季」的预填内容。

**边**，由强到弱。边把一条自动记录与另一条自动记录或手动关联的记录相连；独立（不归入系列）的记录没有边。

| 边 | 强度 | 条件 |
|---|---|---|
| E1 关联关系 | 3 | 一条记录的 `externalMeta.relations` 以同系列关联关系——`prequel`、`sequel`、`parent`、`sideStory` 或 `summary`——指向另一条，任一方向均可。见[资料库关联关系](#资料库关联关系)。 |
| E2 旧规则 | 2 | `displayTitle` 完全相同、修剪后的 `season` 标签不同——1.6.0 之前的规则，保留下来使以前能关联的记录不会失去关联。 |
| E3 基础标题 | 1 | 两条记录共享一个基础键，**除非**它们看起来是重复条目而非不同的季：季数序数相同，且 `firstAirDate` 在同一天或有一方没有 `firstAirDate`。重复条目归 [`duplicate-detection.md`](duplicate-detection.md) 处理。 |

**分组。**

1. 把片库划分为手动关联的系列（按 `seriesId`）、独立（不归入系列）的记录和自动记录，按 `id` 顺序处理记录。
2. 用自动记录之间的边对自动记录做并查集，得到一组自动连通分量。
3. 对每个分量，保留其到每个手动关联的系列的最强边。若恰好一个手动关联的系列持有最强边，整个分量加入它。**平局时不加入任何系列**，因为歧义绝不能把两个用户手动关联的系列融合起来。
4. 没有加入任何系列、且至少有两个成员的分量成为自动归入的系列。

结果是确定性的：同样的记录以任意顺序输入都得到同样的系列，因此每台设备从同样的数据算出同样的分组。记录按标题、基础键和资料库键放进哈希表索引，因此构建大致与片库规模成线性关系。

**系列内的顺序。** 在该系列中带 `order` 的成员排在最前，升序。其余依次按 `firstAirDate`（缺失者排后）、季数序数、`createdAt`、`id` 排序。重排会给每个成员写入连续的 `order`，因此只有当一条自动记录在之后才加入时才会出现混合状态；它排在末尾，用户可以再移动它。

## 建议

管理面板还会提供**建议**，建议从不是自动关联：系列之外、某一对基础键在 `AnimeSearchService.similarityRaw` 下达到 0.6 **且**在顺序感知的 `orderedSimilarity` 下达到 0.5 的记录，按分数从高到低，至多八条。它们捕捉基础键抓不到、又不宜自动关联的配对——`Love Live!` 对 `Love Live! Sunshine!!`，或 `鬼灭之刃 游郭篇` 这样的篇章副标题。

**关联建议**排在最前：资料库把它列为本记录的 `spinOff` 或 `alternative` 的记录，或把本记录这样列出的记录，任一方向均可。它们得分 1.0，所在行的副标题在季标签后追加*衍生作品*或*不同版本*。衍生作品与本作共享世界观，但不是同一系列，因此只提供建议、从不关联。

## 资料库关联关系

自 1.6.0（M2）起，刷新会把各资料库列出的关联作品存进 `externalMeta.relations`——形态见 [`../data-formats.md`](../data-formats.md)，来源见 [`multi-source-search.md`](multi-source-search.md)。仅凭标题，无法把以日文标题记录的第一季与以中文标题记录的续作关联起来；资料库知道答案。

**匹配。** 关联关系的 `targetUrl` 与记录的页面都经 `canonicalDatabaseKey` 归约为**规范键**：`anilist.co/anime/<id>` 为 `anilist:<id>`，`myanimelist.net/anime/<id>` 为 `mal:<id>`，bgm.tv、bangumi.tv 或 chii.in 上的 `/subject/<id>` 为 `bgm:<id>`——三个 bangumi 主机算作同一站点。一条记录的键是其 `infoUrl` 与每个 `externalMeta.ratings[].sourceUrl` 的键。关联关系的键是记录的键之一时，它就指向这条记录，不论两个 URL 用的是哪种协议、主机别名或末尾 slug。

**各类型的作用。**

| 关联类型 | 作用 |
|---|---|
| `prequel`、`sequel`、`parent`、`sideStory`、`summary` | E1 边（强度 3），任一方向 |
| `spinOff`、`alternative` | 仅作建议，在管理面板中加标签 |
| `other` | 无 |

关联关系只需在一侧列出即可：从未刷新过的续作，仍会因其前作的 `sequel` 关联关系而被关联。独立（不归入系列）的记录两端都不得到关联关系边，手动关联的系列仍然从不移动——关联关系边与其他边一样，只挂接自动记录。

**缺失续作提示。** 当记录所在系列的最后一个成员（记录不在任何系列中时为记录本身）列出了一部 `sequel`，而片库中没有任何记录来自其页面时，详情页在系列卡片正上方显示一张卡片：**下一部：<标题>（<来源>）**，例如 `下一部：葬送のフリーレン 第2期（AniList）`，附提示*资料库中列出、但番剧库里还没有。点按即可添加。* 点按后经与*添加下一季*相同的 `extra` 预填（`NextSeasonPrefill.fromRelation`）打开新建页：关联关系的标题、下一季标签，以及一个指向该最后成员、仅在保存时写入的待定关联。在**完整版**构建中，新建页还会像 `autoSearch` 那样立即用该标题启动在线搜索。**商店版**构建只得到预填的标题，不会搜索。关联数据是 `externalMeta` 中的公开元数据，可能经同步到达商店版构建，因此提示在那里也可能出现；只有在线查找受 `AppFlavor.isFull` 限制。

## 手动整理

每个操作都是纯的 `SeriesEditor` 操作，返回要写入的记录；调用方用 `AnimeStorage.addOrUpdateAll` 持久化——一次加载、一次保存、一次自动同步通知。每条写入的记录都得到新的 UTC `modifiedAt`，因为每条都是用户编辑。

- **首次编辑时固化。** 对自动归入的系列的任何手动操作，都会先给当前每个成员写入同一个新 `seriesId`。没有用户操作就绝不固化。
- **关联到系列…**——在管理面板中，用户点按一条建议，或搜索片库后点按一条记录。当前记录取得那条记录的 `seriesId`；若那条记录的系列是自动归入的则先固化它（若它不在任何系列中，则以它开始一个新的手动关联的系列）。独立（不归入系列）的记录失去 `standalone`，被关联的记录失去任何 `order`，因此排在有顺序的成员之后。
- **移出系列**——写入 `{"standalone": true}`。其余成员保持不变。
- **重排**——在管理面板中拖动成员，然后点*保存顺序*：先固化，再给每个成员写入连续的 `order`（1、2、3…）。
- **交给应用自动判断**——移除本记录的 `seriesLink`（旧链接的未知字段保留）。仅当记录有可移除的链接时提供。
- **添加下一季**——打开新建页（`/anime/edit`，`extra: NextSeasonPrefill`），复制最后一个成员的标题，在能读出时递增季标签（`Season 1` → `Season 2`、`第一季` → `第二季`、`2nd Season` → `3rd Season`；标签与标题不一致时用 `Season <n + 1>`），并带一个待定的关联。只有新记录保存时，关联才与被固化的系列一起在一次 `addOrUpdateAll` 中写入。

**自动记录可能跟随被移动的记录。** 关联只写入它指名的记录，但下一次构建仍会运行自动分组。与刚被移动的记录之间有边的自动记录——例如共享其基础标题的另一季——因此可能跟着它进入新的系列。如果这样不对，打开那条记录，使用*移出系列*或把它关联到正确的位置。

## 界面

- **系列卡片。** 详情页的上一季/下一季行变成了 `_buildDetailChildren` 中的*系列*卡片——位置不变，因此在双栏布局中它落在右栏。当记录的系列至少有两个成员时出现，按顺序列出成员（位置、标题、季标签、已看/总数、状态图标），高亮当前成员，点按可打开某个成员，并注明该系列是*手动关联的系列*还是*自动归入*。菜单包含*管理系列…*、*添加下一季*、*移出系列*，以及适用时的*交给应用自动判断*。上一季/下一季按钮仍在它下方，现在由系列顺序驱动，放在 `Wrap` 中，窄屏手机上会换行堆叠。成员行和上一季/下一季按钮会**压栈打开**另一条记录的详情页，路由按 id 为每个详情页设置 key。1.6.0 中它们使用 `context.go`：第一次跳转替换了整个页面栈，没有可返回的页面；第二次跳转复用了同一个页面 State，因此屏幕上什么也没变。
- **缺失续作提示。** 系列卡片上方的一张卡片，只要[资料库列出的续作缺失](#资料库关联关系)就会显示——记录不在任何系列中时也一样。
- **应用栏关联菜单。** 记录不属于任何系列时——包括独立（不归入系列）的记录——卡片不出现，应用栏中的关联图标提供*关联到系列…*、*添加下一季*，以及记录带 `seriesLink` 时的*交给应用自动判断*。
- **管理面板。** 搜索框、建议，以及带拖动手柄的成员。窄窗口下是底部面板，宽窗口下是对话框，由 `canSplitLayout` 选择——没有新的断点；见 [`../adaptive-layout.md`](../adaptive-layout.md)。

详情页的布局见 [`../functions/features/anime/views/anime_detail_page.md`](../functions/features/anime/views/anime_detail_page.md)。

## 交互

- **同步。** `seriesLink` 随普通的整记录合并传输。固化会写入多条记录，每条都是普通的用户编辑，因此另一台设备上对其中某条的并发编辑会成为普通的冲突。两侧 `seriesLink` 不同时，冲突对话框每侧加一行系列说明，使仅关于系列的冲突不会看起来像两个完全相同的版本。见 [`../sync.md`](../sync.md)。
- **分享与导入。** `.myanimeitem` 导出会剥离 `seriesLink`，导入时即使手写文件带有它也会丢弃。见 [`share-and-import.md`](share-and-import.md)。
- **重复合并。** primary 的 `seriesLink` 胜出，否则取第一个后备记录的。同一系列中季标签不同的成员不是重复条目。见 [`duplicate-detection.md`](duplicate-detection.md)。
- **删除记录**无需特殊处理：组 id 留在剩下的成员上。
- **本地 API。** 未改动；其记录投影不包含系列数据。

## 可能的后续工作

按系列对管理列表分组——每个系列一行，可展开为其成员——不属于 1.6.0。索引已能支持，列表布局尚未支持。
